# 第三方组件与许可（原则说明）

> 私有化交付＝**分发**，因此必须把开源许可义务处理干净。
> 本文说明我们的处理原则与交付动作；**具体的组件清单与版本随交付包提供**。
> 版本：2026-10 对外版 v1.0

---

## 一、组件类别

| 类别 | 举例（类别，不含版本） |
|---|---|
| 运行时 | 语言运行时、构建工具链 |
| 数据库 / 缓存 | 关系型数据库、内存缓存 |
| 对象存储 / 检索 | 对象存储、向量检索组件 |
| 媒体处理 | 音频编解码、媒体转换工具 |
| 应用框架 | 后端框架、前端框架、移动端框架 |
| 依赖库 | 各语言生态的第三方库 |
| 模型与素材 | 语音模型权重、字体等（按项目是否本地部署决定） |

---

## 二、处理原则（按许可证类型）

| 许可证类型 | 处理方式 |
|---|---|
| **宽松许可**（MIT / Apache-2.0 / BSD 等） | 允许商用、修改与再分发；**义务＝保留版权与许可声明、注明修改处** |
| **弱/强著佐权**（LGPL / GPL 等） | 逐项处理：替换、进程隔离，**或改由客户自行安装**（不随我方便利分发） |
| **网络服务类许可**（如 SSPL / RSAL 等） | 锁定到宽松许可版本，或替换为兼容的宽松许可实现 |
| **AGPL 类** | 随附许可证与源码获取途径；条件允许时改用宽松许可替代实现 |
| **模型权重** | 逐个核对模型许可证；采用客户自有平台时不涉及本地部署 |

**结论一句话**：风险只出现在"分发"环节；**数据库与中间件让客户自装**是成本最低、也最干净的做法。

---

## 三、交付前动作（我方执行）

1. 依赖许可证扫描：Python 侧、文件系统侧、构建依赖侧各跑一遍；
2. 扫描结果中命中 GPL / AGPL / SSPL 类许可的组件**逐个处理**（替换 / 隔离 / 改由客户自装）；
3. 生成《第三方组件与许可清单》，随交付包提供，包含：组件名、版本、许可证、用途、处理方式；
4. 交付包内**保留各组件的 LICENSE 与版权声明**（宽松许可的强制义务）。

## 四、二次开发说明

部分组件基于开源项目二次开发，相应的许可证与版权声明**在交付包中完整保留**；
我方代码与第三方代码在交付包中**分区说明**，验收时不会混淆。
